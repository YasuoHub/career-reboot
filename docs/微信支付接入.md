# 微信支付接入 · H5 场景落地

> 背景：用户拥有微信经营账户（商户号），支付宝个人账户无法做 H5 网站支付（需企业资质）。
> 所以线上自动化收费**只走微信支付**，单通道。
> 关联文档：[深度报告设计](./深度报告设计.md) / [分享验证方案](./分享验证方案.md)

---

## 一 能做什么 / 不能做什么

| 支付产品 | 支持 | 你的场景匹配度 |
|---|---|---|
| **JSAPI 支付**（微信内 H5/浏览器唤起） | ✅ | **主通道**，用户在微信里打开 → 点解锁 → 直接拉起收银台 |
| Native 支付（扫码） | ✅ | 备选，PC 端访问或老版本兜底 |
| H5 支付（非微信浏览器外跳） | ✅ | 若有非微信浏览器打开（比如微博引流过来），走这个，外跳微信 App 收银台再跳回 |
| App 支付 | ❌ 不适用 | 无 App |
| 小程序支付 | ✅（如果做小程序版） | 远期 |

**主通道 = JSAPI + H5 双版本自动切换**：前端判断 UA 在微信内 → JSAPI；外部浏览器 → H5。

## 二 一次性准备工作（只有第一次要）

### A. 微信商户平台开通
1. 用微信经营账户（商户号 mch_id）登录 [pay.weixin.qq.com](https://pay.weixin.qq.com)
2. Products → App 和 H5 支付 → 开通（JSAPI 是默认就有）
3. 记下：
   - `mch_id`（10 位商户号）
   - `appid`（与公众号/小程序绑定的 appid；H5 内 JSAPI 需要公众号 appid，且公众号已认证）

### B. 域名备案 & 白名单
- `career-turn.icu` 必须**已完成 ICP 备案**（.icu 是国际域名，微信 H5 支付要求域名已备案——这是个大坑，要先查你有没有备过案）
- 在商户平台添加支付授权目录：`https://www.career-turn.icu/*`
- 若没有备案，需要先把域名迁到国内服务商备案一次（阿里云、腾讯云都可以）

### C. API 密钥 & 证书
- 商户平台 → 账户中心 → API 安全 → 设置 APIv3 密钥（32 位随机串，自己记牢）
- 生成 API 证书（apiclient_cert.pem / apiclient_key.pem），用于签名

### D. 回调地址（notify_url）
```
https://www.career-turn.icu/api/pay/notify
```
指向 Vercel Serverless Function（P0 就要写，见第三节）。

### E. 若走公众号网页授权拿 openid（见分享验证文档）
公众号后台 → 功能 → 网页服务 → 网页授权 → 修改授权回调域名为 `www.career-turn.icu`

## 三 服务端支付接口（Serverless Function）

用 Node.js（不引入新语言栈，复用现有技术栈）。三件套：

### `/api/pay/create` —— 下单
```js
// 简化伪代码，实际生产需要 WXPay SDK + 严格签名
export default async (req, res) => {
  const { uid, archetype } = req.body;
  const outTradeNo = `CRB${Date.now()}${uid.slice(-6)}`;  // 商户订单号唯一
  const amount = 990;                                       // 9.9 元 = 990 分
  const description = '重启人格图鉴·深度报告';

  // 判断场景
  const isWechat = /MicroMessenger/i.test(req.headers['user-agent']);
  const scene = isWechat ? 'JSAPI' : 'MWEB';

  // 调微信下单 APIv3（POST https://api.mch.weixin.qq.com/v3/pay/transactions/{scene}）
  // 请求体：appid, mchid, description, out_trade_no, notify_url, amount{total:990},
  //        payer{openid} （JSAPI 需要）, scene_info{client_ip} 等
  // 返回：prepay_id
  ...
  res.json({ prepayId, paySign, timestamp, nonceStr });
};
```

### `/api/pay/notify` —— 支付结果回调
```js
export default async (req, res) => {
  // 1. 校验签名、微信平台证书链
  // 2. 解密 resource.ciphertext（AES-256-GCM，用 APIv3 密钥）
  // 3. 解析 trade_state == 'SUCCESS'
  // 4. 幂等校验（out_trade_no 是否已处理过）
  // 5. 更新 DB：unlock_status[uid] = true, unlock_via = 'pay', paid_at = now()
  // 6. 返回 { code: 'SUCCESS', message: 'OK' }
  // 7. 若处理失败返回 FAIL，微信会重试 8 次
}
```

### `/api/unlock?uid=xxx` —— 解锁状态查询
```js
export default async (req, res) => {
  const { uid } = req.query;
  const row = await db.query('select * from unlocks where uid=$1 and expires_at > now()', uid);
  res.json({ unlocked: !!row, via: row?.via ?? null });  // via ∈ ['pay','share']
}
```

## 四 数据库表（最小可用）

Supabase Postgres 两张表：

```sql
-- 用户基本档案（微信 openid 为主键）
create table if not exists users (
  unionid text primary key,
  nickname text,
  avatar_url text,
  last_seen timestamptz default now()
);

-- 解锁状态（一用户一行，覆盖 30 天）
create table if not exists unlocks (
  unionid text primary key references users(unionid),
  unlocked_at timestamptz not null default now(),
  expires_at timestamptz not null default now() + interval '30 days',
  via text not null check (via in ('pay','share')),
  pay_out_trade_no text unique,       -- 付费时记录微信订单号
  invite_progress int default 0      -- 分享路径进度 0~3
);

-- 推荐关系图谱（供"双人对比报告"和 R1/R2/R3/R4/R5 校验用）
create table if not exists invite_edges (
  id bigint generated by default as identity primary key,
  referrer_unionid text not null,
  viewer_unionid text not null,
  created_at timestamptz default now(),
  unique(referrer_unionid, viewer_unionid)
);
create index on invite_edges(created_at);
```

## 五 前端下单流程（H5 内唤起）

```
用户点「¥9.9 解锁深度报告」
   ↓
检查本地是否有 uid（openid）
   无 → 走微信网页授权跳转（见分享验证方案 §三）拿到 uid
   有 → 继续
   ↓
POST /api/pay/create { uid, archetype }
   ← { prepayId, paySign, timestamp, nonceStr }
   ↓
调用 WeixinJSBridge.invoke('getBrandWCPayRequest', {...}, cb)
   → 微信内直接拉起收银台
   ↓
支付完成 → 微信页面跳回 ?pay_done=1
   ↓
前端 GET /api/unlock?uid=xxx → { unlocked: true, via: 'pay' }
   → 渲染深度报告页（新屏 #sc-report，全屏沉浸）
```

**非微信浏览器**（比如用户从微博链接进来）：
```
同一流程，scene=MWEB
→ 后端返回 h5_url（一个外跳微信 App 的链接）
→ window.location.href = h5_url
→ 用户跳到微信 App 付完
→ 微信 App 跳回 notify_url + 一个 return_url（我们设的）
→ return_url 设为 https://www.career-turn.icu/?pay_done=1&uid=xxx
```

## 六 前端解锁状态的三态展示（关键 UX）

结果页加一块入口，三种状态三种文案：

| 状态 | 触发 | UI 呈现 |
|---|---|---|
| **未解锁** | GET /api/unlock → false | 「解锁深度报告 ¥9.9」+「邀请 3 位好友免费解锁双人对比」两个按钮 |
| **付费解锁** | via='pay' | 直接进 #sc-report，显示"已购买于 YYYY-MM-DD"，不出现分享入口 |
| **分享解锁中** | invite_progress ∈ [1,2] | 显示进度条「已有 2 位好友测完，再邀 1 位解锁双人对比」，隐藏付费按钮 |
| **分享解锁完成** | via='share', invite_progress=3 | 进入双人对比报告页（不显示单人深度报告，避免付费用户觉得吃亏——见下方边界处理）|

**边界处理**：同一份深度报告被两种方式解锁都可能发生，处理方式是——无论 via 是什么，都给一份深度报告；但 via='share' 时额外多给一份双人对比报告。文案上始终不提"等价替换"，让用户从两条路都是"赢得东西"的视角看。

## 七 合规清单（上线前过一遍）

- [ ] 商户号 mch_id 与 appid 绑定主体一致
- [ ] 域名 career-turn.icu 已完成 ICP 备案（**大坑**，.icu 不保证可以，先查）
- [ ] 支付授权目录已加白名单 `https://www.career-turn.icu/*`
- [ ] 9.9 元定价在微信商户平台的类目匹配（虚拟商品/咨询服务，具体类目问客服）
- [ ] 站内显著位置挂《用户协议》+《隐私政策》（免责产品必须挂，给 GTM 加标签也能作为"合规已确认"的证据）
- [ ] 深度报告的显著位置标注"趣味性格探索，不构成医疗、心理诊断或就业承诺"（跟现在轻版免责声明同源）
- [ ] 未成年人提示（可选——"本测试建议 16 周岁以上用户使用"）
- [ ] 数据不留存声明："除微信 openid 外，不采集任何个人敏感信息，深度报告数据仅在本设备生成"

## 八 P0 交付清单（下周一开始）

按时间顺序：
1. 确认域名备案状态（若没备过，先迁到国内服务器+备案，约 1 周）
2. 开通商户号 H5/JSAPI 产品，记下 mch_id/appid/apiv3 密钥
3. 写 3 个 Serverless Functions（Vercel）：/api/pay/create、/api/pay/notify、/api/unlock
4. Supabase 建 3 张表
5. 前端加解锁入口三态 UI
6. 端到端测试：微信内打开 → 点解锁 → 付 9.9 → 跳回 → 出报告
7. 上线一周后拉 GMV / 分享转化率 / 复访率数据，决定 P1 节奏

**风险点**：最不确定的是第 1 步——`.icu` 域名能否在国内完成备案要先查。如果不行，考虑把支付页单独放一个已备案的国内子域，或者接 Stripe（海外付款绕过备案限制）。这块等你把备案状态确认了再启动开发。
